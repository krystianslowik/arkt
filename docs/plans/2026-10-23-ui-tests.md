# UI End-to-End Test Suite Implementation Plan (XCUITest, track U, issue #161)

> Implement this plan task by task, with a review checkpoint after each task. Results go to
> `docs/plans/2026-10-23-ui-tests-results.md`. Tracking issue: #161 (it feeds the parity report of #137).

**Goal:** Add an XCUITest target, `ArktShellUITests`, that launches the real Debug `ArktShell.app` the way a user would.
Each launch gets a throwaway data folder, a throwaway defaults suite and a throwaway (or fixture) Arc folder. Pages are
served by a loopback HTTP server inside the test runner, so the network is never touched. The suite drives the shell
only through accessibility identifiers and covers these flows:
- first run
- New Space
- Cmd-T, Cmd-L
- Toolbar
- hover X and Cmd-W
- Archive restore
- Favorites close
- command bar keys
- Space switching
- Arc import
- quit and relaunch
- recovery toasts
- (later) Split View

Every test names the parity rows it proves (KB / BH / GS). A script turns the `.xcresult` into the parity report that
#137 asks for. The suite runs locally with `xcodebuild test -scheme ArktShellUITests`. In CI it starts as an informative
job and becomes required once it has been stable for a set period.

**Architecture:**
1. **App target, Debug only.** The app already reads `ARKT_DATA_DIR` and `ARKT_ARC_DIR`. It gains:
   - `ARKT_DEFAULTS_SUITE`, so the Toolbar setting never writes the user's real defaults;
   - `ARKT_AUTOSAVE_DELAY_MS`, so the "quit inside the debounce" case is deterministic;
   - a strict `ARKT_UITEST=1` mode that refuses to start unless every override is set;
   - an Info.plist marker (`ArktEnvironmentOverrides`) that the test harness checks before it launches anything.
   None of this exists in Release builds.
2. **ShellUI.** Gains accessibility identifiers only, kept as constants in one dependency-free file (`AXID.swift`). The
   UI test target compiles that same file, so the identifiers can never drift apart.
3. **`ArktShellUITests` (XcodeGen `bundle.ui-testing`).** Owns the harness, which:
   - creates a per-test sandbox (temp data, Arc and defaults);
   - runs the loopback server;
   - copies the Arc fixture into the sandbox with every URL rewritten to the loopback port;
   - provides wait helpers that wait on accessibility values, never sleeps;
   - attaches a screenshot of the window only (not the whole screen) plus the accessibility tree on failure.
   The tests never look into web content's accessibility tree. That is what keeps them engine-agnostic: the same suite
   runs unchanged against the Chromium build (#33) through `ARKT_UITEST_APP`.

**Tech Stack:** Xcode 26.6 on CI (`macos-26` image), Xcode 27.1 locally; XcodeGen 2.46.0; XCTest/XCUITest
(`XCUIApplication(url:)`, `XCUIElement.hover()`, `typeKey`, `XCTNSPredicateExpectation`); Network.framework for the
loopback server; CryptoKit for fixture checksums; `xcrun xcresulttool` and `/usr/bin/jq` for the report. No new
third-party dependencies.

  CORE=$REPO/app/ArktCore; UIT=$APP/UITests; DD=$APP/build`
- **One branch per task**, `<type>/<issue#>-<slug>` (CONTRIBUTING section 4). Each task has one issue (U4a, U4b and U4c

- **Hot files** (CONTRIBUTING, "Repo hot files"): `project.yml`, `ShellWindowController.swift`,
  `SidebarController.swift`, `MainMenu.swift`, `.github/workflows/swift-tests.yml`, `CONTRIBUTING.md`. Keep each edit to
  these small and in its own commit, and rebase on `main` before review.
- **Capacity rule.** While a Chromium build runs: `nice -n 20`, `-jobs 2`, at most two Swift builds at once.
- **Never touch real data.** Every rule below is enforced by the harness, not just asked for:
  - Every app launch from a UI test sets `ARKT_UITEST=1`, `ARKT_DATA_DIR`, `ARKT_ARC_DIR` and `ARKT_DEFAULTS_SUITE`, all
    pointing into a per-test temp sandbox. Set `ARKT_ARC_DIR` even when no import is wanted: point it at an empty
    directory, so the existence check never looks at `~/Library/Application Support/Arc`.
  - Launch arguments always include `-ApplePersistenceIgnoreState YES -NSQuitAlwaysKeepsWindows NO -AppleLanguages (en)
    -AppleLocale en_US`.
  - The harness refuses to launch an app whose Info.plist lacks `ArktEnvironmentOverrides = YES` (Debug only).
  - `ARKT_SMOKE` and `-ArktSmoke` are never passed, except by the one seeding helper that reuses the E6
    `ARKT_SMOKE=import` phase (U6).
  - Never open, copy or grep the real Arc folder. Fixtures are copies of
    `$CORE/Tests/ArcImportTests/Fixtures/*-synthetic.json` made at test time, and the files under `Fixtures/` are never
    edited.
- **No network.**
  - Tests type only `http://127.0.0.1:<port>/...` URLs.
  - Never type text into the command bar that `URLInputParser` would treat as a query (it commits to
    `https://www.google.com/search?q=`).
  - No `file://` pages: the parser treats `file://` as a query, so it would go to Google too.
  - The FakeEngine favicon fetch (`/favicon.ico` relative to the page) stays on loopback; the server answers it with
    404.
  - U5 adds a source check that fails on any `http` or `https` literal in `$UIT` other than `127.0.0.1` and the fixture
    placeholder.
- **Engine-agnostic.** Assert only on shell accessibility: identifiers, labels, `value`, `isEnabled`, `isSelected`.
  Never query the web view's accessibility tree, never inject JavaScript, never read pixels. "Page loaded" means one of:
  - the tab row's label equals the fixture page's `<title>`;
  - the URL bar's `value` contains the path;
  - toolbar Back or Forward `isEnabled` changes.
- **No sleeps.** `sleep`, `usleep`, `Thread.sleep` and `Task.sleep` are forbidden in `$UIT` (U5 adds the check). Wait
  for an accessibility state with the harness helpers (`waitFor(_:value:)`, `waitUntilGone`, `waitFor(app,
  .notRunning)`).
- **Retry policy: none.** Never pass `-retry-tests-on-failure`, and set no `XCTestCase` retries. A flaky test is fixed
  in the same pull request, or skipped with `throw XCTSkip("flaky: #NNN")` and a linked issue. The report shows it as
  deferred.
- **Quitting.** A test that checks persistence quits with `app.typeKey("q", modifierFlags: .command)` and then waits for
  `.notRunning`, so the real `applicationShouldTerminate` flush runs. `app.terminate()` (a kill) is used only in
  `tearDown` to clean up after a failure.
- **Parity naming.** Test methods are named `test_<ROW>[_<ROW>...]_<behavior>`, with ids written without the dash:
  `test_KB001_BH100_cmdTOpensURLInNewTodayTab`. Rows marked NEEDS-RUNTIME-CHECK assert Arkt's current [I] default and
  say so in a comment `PARITY(NEEDS-RUNTIME-CHECK RT-xx)`.
- No emojis anywhere. TDD for app hooks and identifiers: the in-process test first, watch it fail, implement, run again.
- **Commits.** Stage explicit pathspecs (`git add <paths>`, never `-A` or `.`), write plain messages, and use the GitHub
  noreply author.
- **Commands:**
  - Core: `cd $CORE && nice -n 20 swift test -j 2 2>&1 | tail -5`
  - ShellKit pure: `cd $KIT && nice -n 20 swift test -j 2 --skip ShellKitGUITests 2>&1 | tail -5`
  - ShellKit GUI (logged-in session): `cd $KIT && nice -n 20 swift test -j 2 --filter ShellKitGUITests 2>&1 | tail -5`
  - App build: `cd $APP && xcodegen generate && nice -n 20 xcodebuild -project ArktShell.xcodeproj -scheme ArktShell
    -configuration Debug -derivedDataPath $DD -jobs 2 build 2>&1 | tail -3`
  - UI tests, all: `cd $APP && xcodegen generate && nice -n 20 xcodebuild -project ArktShell.xcodeproj -scheme
    ArktShellUITests -derivedDataPath $DD -jobs 2 -resultBundlePath $DD/ui-$(date +%s).xcresult test 2>&1 | tail -25`
  - UI tests, one: add `-only-testing:ArktShellUITests/<Class>/<test>`
  - UI stability run (before promotion): add `-test-iterations 20 -run-tests-until-failure`
- While the UI tests run, do not use the mouse or keyboard. `hover()` moves the real pointer and `typeKey` goes to the
  frontmost app. The display must be awake and unlocked.

1. Enable developer mode for the tools: `DevToolsSecurity -enable`. Your account must be in the `_developer` group (the
   command asks for an admin password once).
2. So that UI testing does not ask for a password on every run: `automationmodetool
   enable-automationmode-without-authentication` (admin password once).
3. On the first `xcodebuild test`, macOS asks to let the test runner (or Terminal / Xcode) control the computer. Allow
   it in System Settings > Privacy & Security > Accessibility, and Automation if prompted. If the prompt was dismissed,
   add Terminal (or the terminal app you use) there manually and run again.
4. Signing stays ad hoc (`CODE_SIGN_IDENTITY: "-"` from `project.yml`). No Apple Development identity is needed for the
   Debug UI run. Identity names are never committed.

GitHub-hosted `macos-26` runners come with automation mode and the TCC grants already set up for UI testing. U3 verifies
this instead of assuming it.

## Decisions fixed for this track

1. **XCUITest drives the real app, not views.** In-process `ShellKitGUITests` stay the place for view logic and frame
   timing. This suite checks wiring end to end (menu, responder chain, app session, database, engine) and only through
   accessibility. No frame-timing asserts in this suite, ever.
2. **Local pages come from a loopback HTTP server inside the test runner** (ephemeral port, `requiredInterfaceType =
   .loopback`), not from `file://`. Reasons:
   - the command bar parser rejects `file://` as a URL;
   - Chromium and WKWebView treat file pages differently (sandbox, titles, history);
   - a real origin gives back/forward history and favicons the same way on both engines.
   The server serves `/p/<name>` as `<title>Fixture <name></title>` with a link to `/p/<name>-next`. Any other path
   returns the same generic page titled after the path, so rewritten Arc fixture URLs always load.
3. **Arc fixtures are rendered per test.** The synthetic `StorableSidebar-synthetic.json` and
   `StorableArchiveItems-synthetic.json` are bundled as resources by path reference (no copy in the repo). At run time
   each is written into the sandbox Arc folder with `https://example.com` replaced by `http://127.0.0.1:<port>`. A
   SHA-256 of the rendered copy is taken before the app starts.
4. **Seeding.** A test that needs Spaces or Favorites before it starts calls `Sandbox.seedFromArcFixture()`. That
   launches the app once with `ARKT_SMOKE=import` (the existing E6 Debug phase: import, print one line, quit through
   `applicationShouldTerminate`) and waits for `.notRunning`, so seeding uses product code only. The UI test target
   never links `Persistence` or GRDB (the CI isolation grep forbids it outside `App/`).
5. **Strict test mode.**
   - When `ARKT_UITEST=1` is set, a Debug app that is missing any of `ARKT_DATA_DIR`, `ARKT_ARC_DIR` or
     `ARKT_DEFAULTS_SUITE` writes one log line and exits with code 64 before it opens anything.
   - Release builds have none of these hooks, and their Info.plist says `ArktEnvironmentOverrides = NO`. The harness
     reads that key from the target app bundle and fails the test before launch unless it is `YES`.
6. **Engine selection.** The test runner reads `ARKT_UITEST_APP`, the path to an `.app`, passed through
   `TEST_RUNNER_ARKT_UITEST_APP=...`. When set, it launches that bundle with `XCUIApplication(url:)`; otherwise it
   launches the target application `ArktShell`. The Chromium build must honor the same environment keys. It must also
   keep its engine user-data-dir under `ARKT_DATA_DIR` (or a sibling `ARKT_ENGINE_DATA_DIR` the harness also sets) and
   use a mock keychain. That requirement is added to #33 and #128 as an acceptance criterion; this track does not
   implement it.
7. **Failure artifacts.**
   - On failure, `tearDown` attaches `app.windows["shell.window"].screenshot()` (the Arkt window only, never
     `XCUIScreen.main`, so other apps on a developer's screen never land in an artifact).
   - It also attaches `app.debugDescription` (the accessibility tree) and the sandbox file listing (names and sizes
     only).
   - All attachments use `lifetime = .keepAlways`.
   - The content is synthetic (loopback pages, fixture titles), so it may be uploaded from CI.
8. **CI.** A new job, `UI tests (informative)`, starts with `continue-on-error: true` and stays out of the `Swift tests`
   gate. It is promoted to required in U16 only after 10 consecutive green runs on `main` and a local 20-iteration run
   without a failure.

6. **Promotion** (separate pull request, maintainer decision, recorded in #161). Criteria:

   - one local `-test-iterations 20 -run-tests-until-failure` run with no failure;

## Runtime budget

| Item | Local dev Mac | CI `macos-26` |
|---|---|---|
| App launch to `shell.window` | under 2 s | under 6 s |
| One scenario test (1 to 3 launches) | under 15 s | under 45 s |
| Seeded test (import phase plus launch) | under 8 s extra | under 20 s extra |
| Whole suite at the end of U14 (about 45 tests) | under 6 min | under 20 min, job timeout 40 min |
| Per-test `executionTimeAllowance` | 60 s | 60 s (rounded up by XCTest to the minute) |

Wait timeouts default to 10 s and are scaled by `ARKT_UITEST_TIMEOUT_SCALE` (3 on CI). A test needing a longer timeout
says why in a comment. If the suite goes over budget, split it into two test plans (`smoke`: U2, U7, U14; `full`:
everything). Only `smoke` would then be promoted to required.

## Flakiness strategy

- Every launch gets a fresh sandbox and a fresh defaults suite. No test depends on another test's state or on order
  (`-parallel-testing-enabled NO`; the tests share the real pointer and keyboard).
- Waits target accessibility state (`value`, `label`, `isEnabled`, `isSelected`, existence) through predicates. Never
  sleep (CI check). Never assert during an animation: hover-X waits for `isHittable`, toasts wait for existence and then
  label.
- No retries (Rules). A test that fails once on `main` gets an issue within a day: fix it, or skip it with the issue id
  so it shows as deferred.
- Engine nondeterminism is kept out by loopback pages with fixed titles and no external resources, `nonPersistent`
  WKWebView data (already the FakeEngine's), and, for Chromium, a throwaway user-data-dir under the sandbox (decision
  6).
- Timing is never asserted in this suite; frame gates stay in `ShellKitGUITests` and S9.
- Before promotion, and after any change to the harness, run 20 iterations locally.

## Out of scope

- Frame-time and latency gates (ShellKitGUITests, SmokeRunner, S9).
- Real trackpad gestures, fullscreen and second-desktop Cmd-T, 1x/2x display moves (#26).
- Driving a fresh Arc for NEEDS-RUNTIME-CHECK rows (#78); tests assert Arkt's [I] defaults until #78 updates the spec.
- Content-level checks inside web pages, extensions, the Web Store (engine smoke, #33 and W-tasks).
- Building Chromium in CI.
