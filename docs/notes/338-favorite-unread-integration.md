# Favorite unread integration test contract (#338)

The tests run on the main actor. Title and favicon events are synchronous in the in-memory engine; no timers or per-frame work are needed. The hot path is the sidebar tile refresh. Worst cases exercised are empty titles, zero, 1 and 99+, the minimum tile width and light/dark flavors. Geometry checks cover bounds and intrinsic text size, not pixels or contrast.

Integration order:

1. Add typed, independently persisted badge preferences and reset behavior in `app/ArktCore/Sources/Persistence/SettingsStore.swift` or its settings group; wire loading, saving and updates through `app/ArktShell/App/AppSession.swift` and the appropriate Settings UI. The proposed test name is `FavoriteBadgePreferences`; map it to a ShellUI value rather than importing Persistence into ShellUI. Defaults require a product decision if not already specified. Broadcast changes to every window, including off/back-on without a title event.
2. In `app/ArktShell/ShellKit/Sources/ShellUI/Window/ShellWindowController.swift`, feed the actual snapshot title during replay and every title event, including empty, into window-local live state. Keep the existing persisted-title handling for empty titles. Clear live state on close, removal and handoff; do not infer a live title from the saved display name. Connect settings to `Sidebar/SidebarController.swift` and target the affected tile.
3. In `Sidebar/FavoritesGridView.swift`, configure and clear a badge on reuse, expose its count in the existing accessibility value description, post value changes, and preserve the label, loaded/current value, press, menu and close actions. The tests propose `unreadBadgeView` (an inspectable text view) and `favoriteBadgeSettings` on the window; adapt names if the implementation has equivalent observable seams. Preserve the existing callback paths.
4. Integrate #822 hover deferral and #802 split close/menu changes in their landing order, preserving both sets of callbacks. Reconcile badge geometry with #824 and favicon metadata/picker changes with #832 when those changes land; rerun hit testing, targeted updates and bounds tests after integration. These overlaps do not require production changes in this test commit.
5. Favorite music indication has no grid seam today: audio updates reach the outline. Coexistence with that indicator belongs to #117 and needs tests when its design and seam exist. Live Calendar Join remains unplanned (OS-06).

`FavoriteUnreadIntegrationTests` is intentionally test-first and currently refers to the proposed missing APIs; `FavoriteBadgeSettingsTests` likewise defines the persistence contract. Local parsing is not an observed red test run. Run the focused GUI and persistence tests on a complete supported build environment first, confirm the expected missing-integration red, then implement and run the relevant full CI suites. Rendering pixels, contrast and actual site title formats still need verification.
