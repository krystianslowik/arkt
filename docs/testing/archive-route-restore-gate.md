# Archive restore routing gate (#113)

Base: `6d37d7c6f66e0638cf781d8cb5a405f77ae5c378`. This is a test-only proposal for root review and publication; observe the intended red before implementing it. No local GUI run or compilation is claimed.

`ArchiveListModelTests.matchingRouteRestoresArchiveRowIntoItsDestination` drives the Archive window's existing data-source action, the real coordinator and in-memory sidebar/archive stores. All three Spaces use the same default profile. Parameterized contains and exact cases use different URLs and destinations, with a nonmatching rule before either match. A case-insensitive explicit route sends a Today tab to a different existing Space despite both the original and current Space existing. The test checks the restored snapshot and identity, neighboring rows, returned location, archive row and store removal. Destination membership and count are checked without specifying a new routed insertion-order policy. Existing coordinator tests cover ordinary original-Space and fallback restores, retries and id collisions.

The test proposes `ArchiveCoordinator.linkRoutingProvider: (@MainActor () -> LinkRouting?)?`. An absent provider retains the historical path; a configured provider returning nil means routing is unavailable. In that state restore reports failure without mutating the sidebar, hiding the row, or removing its archive entry. The retained row can be retried after the provider supplies a loaded snapshot. This is a readiness/error contract, not an unmatched-destination policy. The app would supply the shared loaded routing value; this is an input seam, not a test-side resolver. The coordinator must distinguish an explicit match from the default and route the tab during the existing restore transaction. Passing a matching Space as today's `fallbackSpace` is insufficient: `Archiver.restore` explicitly prefers an existing source Space. The precise production API is reviewable and may be changed alongside the test before publishing; the change must retain archive outbox, error and snapshot semantics. App composition must handle unavailable routing state deliberately rather than pretending a default value was loaded.

The intended first failure is a compiler error for the missing provider, not a measured result. The test has only been parsed, not compiled or executed. Run the focused CoreBridge test in CI on the required toolchain after review and publication, confirm its first failure is attributable to that missing seam, and record the observed red before production work. No GUI count is claimed.

BH-157 covers external links, Peeks and archive restores; BH-086 says restores return to the original Space while obeying routes. The [maintainer decision](https://github.com/krystianslowik/arkt/pull/825#issuecomment-6721408579) specifies case-insensitive contains, exact unnormalized matches and first match. BH-156's default is stated for links from another app, not unmatched restores. Design section 4 step 4 makes Arc route import optional. This gate does not decide unmatched/default Little Arkt, other route destinations, cross-profile policy, folders or splits. For unmatched restores, the minimal choices are preserve the current original/fallback behavior or apply the configured external-link default; the latter needs a decision, especially for Little Arkt. Folder/split matching and routed destinations other than same-profile Space likewise need their own specified behavior and tests.

The Archive window uses `ArchiveListModel.restore`; command-bar search and Reopen Closed use the coordinator separately. `AppSession.didRestore` reports the toast and loads favicons; the downloads Library is a separate window, not this archive restore path. Peek's `decide` and `adoptOpenedTab` still use `PeekRouting` and need separate adoption. Optional Arc import, remaining destination behavior, startup adoption and the native cold-launch environment issue are outside this gate.

Review repairs cover unavailable-state failure and retry, two distinct explicit matches behind a nonmatching first rule, and destination membership without a new order requirement. These remain uncompiled test-only contracts; no production routing implementation or runtime red is claimed.
